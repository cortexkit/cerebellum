# SUBTREE hashes, not commit shas.
# 
# Each line is `git rev-parse <rev>:crates/<crate>` -- the hash of the crate's
# CONTENT. scripts/release-build.sh compares these against the sibling checkout
# at HEAD and refuses to build when they differ, so a release cannot link
# sibling code no gate has verified.
# 
# Content-addressed on purpose, and it matters twice. A sibling commit that
# touches only documentation moves no subtree, so it does not fail a release
# build for a change this binary cannot link. And a history rewrite that
# preserves content leaves these untouched, where commit shas would be orphaned
# by it -- which is what happened on 2026-08-27 and is why these are not shas.
#
